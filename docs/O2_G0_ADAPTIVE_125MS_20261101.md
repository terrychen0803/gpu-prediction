# RTX3090 O2 G0 adaptive calibration and formal validation

Independent protocol: **o2_g0_adaptive_host_125ms_v1_20261101**. Source: [g0_adaptive.py](../o2_sequence/g0_adaptive.py). This does not change O2 V3, its trace labels, or any earlier experiment.

## Evidence and rationale

- RTX3090 60-template G0-only ablation: 540/540 completed, n=8 stable 34/60; n=256 stable 54/60; n=512 stable 55/60 (3-repeat spread <=5%).
- n=256 and n=512 failures overlap in only one template. 512 is not uniformly more stable.
- Group duration median: 2.02ms (8), 63.28ms (256), 126.30ms (512); n=512 minimum group 90.26ms.
- Longer windows generally improve repeatability, but fixed window size is not a universal guarantee. Per-template Bootstrap is therefore an **experimental hypothesis**, not a previously validated solution.

## Frozen measurement policy

- All **60 O2 V3 formal templates**, 30 independent and 30 dependent-tail. Same inputs, shapes, O1 folds, one CUDA stream, FP16, 10 warmup sequences, eager execution, no per-step sync and no Nsight.
- Metric: full-sequence host batch timing, divided by the number of sequences. Group boundaries use CUDA synchronization.
- Bootstrap: 256 sequences/group, 5 groups/process, 2 fresh processes/template = **120 processes**.
- Robust estimate: median over all 10 bootstrap group per-sequence times.
- Nominal target: 125,000 us/group, rounded up to a multiple of 64 sequences/group. Minimum 64, cap 4096. Fail before formal if a count exceeds cap.
- Calibration is frozen in calibration.json and calibration.sha256; worker verifies both template count and calibration hash.
- Formal: 3 fresh independent processes/template = **180 processes**, 5 groups/process, shuffled order, each using frozen calibrated count.
- Review: repeat median spread <=5%, empirical minimum/median group duration, whether each template's **all 15 formal groups** reached >=100ms, unstable-template lists.
- Script stops at first failed worker, does not resume or overwrite preexisting data, and never deletes old data.

## RTX3090 runbook

From a new SSH/tmux session, ensure the GPU has no other CUDA jobs or Kubernetes workload:

```bash
conda activate gpu-prediction-o1
cd ~/RTchen/gpu-prediction-o2-g0-v4
git status --short
git pull --ff-only origin o2-g0-window-pilot-20261101
git rev-parse HEAD
python -m unittest discover -s tests -p 'test_o2_g0_adaptive.py' -v
export CUDA_VISIBLE_DEVICES=0
nvidia-smi
```

Start Bootstrap using a **previously nonexistent** output directory:

```bash
ROOT="$HOME/RTchen/o2-runs/rtx3090_o2_g0_adaptive_125ms_20261101_001"
python -m o2_sequence.g0_adaptive bootstrap --expect-gpu 3090 --out "$ROOT"
```

After it reports 120/120, freeze calibration and verify SHA-256:

```bash
python -m o2_sequence.g0_adaptive calibrate --root "$ROOT"
(cd "$ROOT" && sha256sum -c calibration.sha256)
```

After frozen calibration and only once the GPU is idle, run the independent formal validation:

```bash
python -m o2_sequence.g0_adaptive formal --root "$ROOT"
python -m o2_sequence.g0_adaptive review --root "$ROOT"
```

Expected files include root bootstrap_plan.json, calibration.json, calibration.sha256, formal_plan.json, input_inventory.json, inputs/ plus bootstrap/<template>/run01..02, formal/<template>/run01..03, analysis/timing_quality.csv, analysis/summary.json. Keep worker logs, group timings and GPU snapshots. Do not edit calibration manually.

## Interpretation and safety

A **125ms nominal target does not guarantee every group reaches 100ms**. Separate collection success from stability success. The three formal repeats are disjoint from bootstrap. Calibration parameters are not refitted using formal results.

G0's host-batch endpoint differs from V3 8-sequence G0 and does not independently verify P/R trace reference completeness. Existing V3 O2 reference coverage remained 0 verified steps because all 180 pairs carried NVTX capture warnings.

This code is available on GitHub, but **RTX3090 execution and test results remain to be verified by the node operator**. Until verified new artifacts are archived remotely and SHA-256 checked, keep old O2, clean O2, G0-only control, 5-template Pilot, 60-template Ablation, O1 data and the remote archives.
