# S3 範圍與時間：分批收有用資料

2026-11-07。此為後續建議，尚未執行／未產生新資產，不改舊凍結174配置計畫及S1/S2協定。

S3全量剩138配置（108 base＋30 controls），40×3是1,242 formal cells、49,680 measured；若全做Smoke另414cells。S2實際33配置含Smoke、guard、worker、Nsight/export/audit配對，UTC22:04:42.801790～22:44:36.265011，共39分53秒。線性估算138配置約2小時47分；加25%餘裕約3小時29分，建議每節點先預留3～4小時以上。較大shape／記憶體／失敗另可能增加。這是牆鐘預算，不是純GPU compute時間，也不含前置工程及全部獨立重播／報告。RTX尚無本協定實測耗時，不能保證一樣。

全量不是目前必要門檻。保留40×3獨立程序協定，優先縮小配置範圍。建議先做最多36配置，分三批（各最多12）：

1. 12個train controls，候選為Conv00 stride2、channels_last、kernel1、groups4；Depthwise00 groups=C/2；GEMM00右轉置view；BMM00右轉置view；Linear00 bias-off；BN00 channels_last；Add00 broadcast；Resize00 align_corners；Concat00 channels_last。需依catalog核對具體ID／runtime args並凍結；bias-off對照不會反向證明原memset是0B。
2. 12個anchor01 validation（各家族一配置），檢查獨立signature與連通群，僅train／validation選特徵、超參數及是否擴充。
3. 12個anchor02 exploratory test，先凍結配置與split，收後封存，不依test模型誤差篩選配置或挑下一輪。收集品質異常可記錄但不以改善成績為由排除樣本。

36配置按GB10本輪約44分鐘，留餘裕約55～60分鐘；每12配置約15～20分鐘。先完成controls／validation也可，不必等test或其他節點。每類僅1個validation／test配置仍很薄，不能視為可靠正式泛化確認；已反覆接觸的舊test也不會因凍結恢復未見性。實際R signature若跨split碰撞，要在模型評估前整群處理並保存清單，不以觀察test成績後才搬群。

後續是否補其他102配置，依train/validation的資訊增益、可辨識性及新context需求決定。Conv→BN→ReLU、Residual等小型context工程值得平行準備；目前DAG adapter未完成，不能稱已收集或PASS。資料量增加本身不解除NVTX、unmatched API、clock或label可信度問題。

三節點可各自平行執行有用子集，不需全矩陣逐一同步；跨設備比較再按定義、資產hash、執行範圍與label kind取可比交集。GB10的3～4小時估計不應直接乘三當作同步收集的日曆時間。
