## 3. I1 CUPTI 直接觀測：GB10 與 RTX 3090

Standalone CUPTI `cudaMemsetAsync` Callback Control 成功取得 64B、0B 各一次，API entry/exit 配對及成功 return code 均正確；未與 Nsight 同時執行。

RN-A 使用完全相同 frozen assets。GB10 v2 與 3090 使用相同 PyTorch/TorchVision/CUDA 版本標示與 precision flags：

```
tf32=fp32_precision=ieee; cudnn_benchmark=false;
cudnn_deterministic=false; fp16_reduced_precision_reduction=false;
autocast=false
```

三次 forward 各 **175** 個 ATen Operation，逐項 `aten + shapes + dtypes` 有序簽章 **3/3 跨節點相同**；3090 的三次簽章 SHA-256 均為 `cba0428beb4b9a704b1af4b358d6e4fa85c0edaf63c307bd08418fd790a60305`（此 hash 僅對紀錄中指定的 canonical JSON 序列化規則）。RN-A correctness passed；3090 CPU FP32 relative L2 = 0.0016349845100194216。

| Memset per forward | GB10 v2 | RTX 3090 |
| --- | --- | --- |
| API count | **17** | **4** |
| Positive count | 16 | 4 |
| Zero-byte API | 1 | 0 |
| Byte distribution | 384B × 4; 64B × 5; 512B × 5; 128B × 2; 0B × 1 | 256B × 1; 128B × 3 |
| `op140` (`aten.conv2d.default`, input `[1,1024,14,14]`, weight `[512,1024,1,1]`) | 1 callback，count=0 | **無 Memset callback** |
| Callback entry/exit 與成功 return | 17/17 | 4/4 |
| 三次前向重現 | 是 | 是 |

3090 在 `op081` 提交 256B，`op143`/`op155`/`op165` 各 128B；每次相同。歷史 `memset_rna_20261106T124907Z` 的 `STATUS.json` **維持 failed**，原因為當時 v2 實作把 `op140` 的 **3 次**呼叫寫成硬性斷言；不是因為 CUDA correctness 或 12/12 Callback 失敗。新程式將該特殊假設移至 **device-specific diagnostic**；不回寫舊 status、不冒稱舊 Nsight API 缺失都是 0B。

**結論範圍：** 相同高階 ATen 有序簽章 **不保證** 相同 `cudaMemsetAsync` API 序列。不能據此推論所有 GPU kernel 序列均不同，或將原因唯一歸於 GPU 晶片；cuDNN algorithm、driver、host/toolchain 和其他底層 stack 差異仍可能影響。

## 5. 後續順序與研究邊界

1. I1 新版 standalone Observer：保留已捕獲 API 的 entry/exit/count/return 驗證；跨 GPU `op140` 不同另列，不讓原 v2 failed run 變 PASS。需要新 run、新 protocol/hash；本檔只保存現有證據。
2. I2 Nsight 3.31：僅在 SQLite schema/必需欄位/完整性檢查通過後允許 read-only 分析，仍保留 warning、timestamp/overlap、reverse-API、Reference gate。新 parser 的結構檢查 **不等於** 3.31 全語意等價或 strict Reference。
3. RTX 3090 **先 RN-A P/R 小型 smoke**，審核已知 scope、GPU/API、同設備 signature、warnings、schema；再執行 MV-A、SW-A、UN-A、YO-A、QP-A、QD-A 的 GI/P/R。任何失敗保留，下一步不重用舊 `--out`。
4. 舊凍結 40×3 `o4_pilot` small-operator / RN-A pilot 使用另外的 OLD checkout、自己的資產/協定，不與新七個 A 的 3-measured smoke 混為同一測量。
5. 完成 RTX 3090 的工程盤點後再部署 RTX 4090；主線仍是 4090 source P → GB10/3090，目標 test P/GI/reference 僅 evaluator 可讀。Reference 沒有足夠證據時允許工程 inventory，但 **不允許正式逐算子模型訓練或宣稱已 verified**。
